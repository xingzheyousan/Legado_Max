# Web 服务端到端（E2E）测试规范

> 本文件是**强制规范**：改动内置 Web 服务的行为性代码后，声称"完成"前必须满足本文件的验证要求。操作命令、UI 自动化路径与工具坑清单见手册《docs/architecture/Web服务端到端测试方法.md》。

## 1. 适用范围与触发时机

改动以下区域且**行为受影响**时（含 Vue 产物重建、路由/控制器改动、响应格式变化），提交并声称完成前必须完成 §3 的三层验证：

- `app/src/main/java/io/legado/app/web/`（HttpServer、WebSocket）
- `app/src/main/java/io/legado/app/api/`（各 Controller 与 ReturnData 契约）
- `app/src/main/assets/web/`（上传页、Vue 构建产物、帮助文档之外的页面资产）
- `modules/web/src/`（Vue 前端源码）

纯格式化、注释、文档改动豁免。

## 2. 为什么单测/编译不能替代

横跨「浏览器 ↔ HTTP 服务 ↔ App 存储/系统」的改动，其 bug 多半藏在层间接缝上（真实案例：serve() 重写 content-type 时剥掉 multipart boundary，编译、单测、审读全部通过，只有真实请求能暴露）。**接口层的真实请求验证不可省略，不得以编译通过或单元测试通过替代。**

## 3. 三层验证与验收标准

| 层     | 验证方式                                                                                             | 验收标准                                                                                                               |
| ------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 接口层 | 对设备实际运行的服务发真实请求（curl 等），**含至少一条失败/边界路径**（未配置前置条件、非法参数等） | 成功与失败都返回约定契约（`isSuccess`/`errorMsg`）；产物有效（zip 可解压、文件确实落盘）；路由变体（如尾斜杠）行为正确 |
| 网页层 | 浏览器真实操作页面（人工或 browser-use 自动化）                                                      | 页面触发预期行为（上传判定、下载事件），结果面板/错误提示按真实服务端结果渲染，不得误报成功                            |
| App 端 | 验证用户可见效果                                                                                     | Toast 实际弹出（可经 logcat 确认）、数据在界面出现（书架 UI 树）、文件落在配置目录                                     |

## 4. 环境降级策略

- 模拟器/设备可用：完整跑三层。
- 仅有可运行包但无设备：至少完成接口层验证（本地起服务或转发），并明确说明未覆盖网页层/App 端。
- 环境完全不允许运行：按 `testing.md` 的弹性约定处理，但**必须显式声明未做运行验证**，不得默认视为已验证。

## 5. 完成定义

- 三层验证（或按 §4 声明的降级范围）全部通过，失败路径有实测证据；
- 用户可见改动已按 `update-log-rules.md` 维护 updateLog.md；
- 手册《Web服务端到端测试方法.md》第九节的复现清单可完整走通。
